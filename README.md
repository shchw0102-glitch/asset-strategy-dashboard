# Asset Strategy Dashboard

**Android 설치형 APK를 지원합니다.** PC·Node.js·Termux 없이 스마트폰에서 독립 실행합니다. 설치·기존 데이터 이전·APK/AAB 빌드 방법은 [ANDROID.md](ANDROID.md)를 확인하세요. 아래 Node.js 실행법은 PC 웹 버전용입니다.

현재 자산·부채를 관리하고 CNTN·CC 가격, 분할매도, 추가 대출 투자, 아파트 매수에 따른 순자산을 계산하는 한국어 웹앱입니다. React + TypeScript + Vite와 Node.js 내장 HTTP 서버를 사용합니다. 앱과 로컬 시세 서버가 하나의 실행 명령으로 켜집니다. 회원가입, API 키, 데이터베이스 설치는 필요 없습니다.

**연결 버전: 업비트 CC 실시간 시세 + Yahoo Finance CNTN·추가 주식·USD/KRW 환율 자동 조회.** CNTN $3, CC 170원, 환율 1,400원은 첫 조회 실패 시 사용하는 **수동 예시값**입니다. 대출 B 만기 60개월도 예시입니다. 입력한 수량·원금·자산·대출은 이 브라우저에만 저장되며 시세 제공처에 전송하지 않습니다.

## 1. 가장 쉬운 실행: Windows에서 더블클릭

1. [Node.js 공식 홈페이지](https://nodejs.org/)에서 **24 LTS 최신 버전**을 한 번 설치합니다. 최소 버전은 **24.10.0**입니다.
2. 제공된 최종 프로젝트 ZIP을 **모두 압축 풀기**로 풉니다.
3. 폴더 안의 **`실행하기.cmd`**를 더블클릭합니다.
4. 최종 ZIP에는 빌드된 앱도 들어 있어 Node.js만 설치하면 바로 브라우저를 엽니다. 빌드 파일이 없는 소스만 받은 경우에는 필요한 패키지 설치·빌드를 자동 수행합니다. 앱을 쓰는 동안 실행창을 열어 두세요.
5. 첫 화면의 시세 카드에서 **자동 조회**와 조회 시각을 확인하세요. 수동 가격을 입력하려면 해당 카드에서 **수동 입력**으로 바꾸세요.

주가·환율 연결은 로컬 시세 서버가 필요합니다. **HTML 파일만 더블클릭하거나 GitHub Pages 같은 정적 호스팅에 올리는 방식에서는 주가·환율 자동 조회가 작동하지 않습니다.** 단일 HTML은 수동 계산용 보조 파일입니다. CC는 브라우저가 업비트 WebSocket 연결을 허용하면 HTML에서도 연결되지만, 전체 기능은 위 실행 방법을 사용하세요.

인터넷이 끊겨도 7개 메뉴의 계산과 저장은 동작합니다. 이전에 조회한 가격이 있으면 마지막 가격·시각을 표시하고, 없다면 사용자 수동값을 사용합니다. 이를 실시간 시세로 표시하지 않습니다.

## 2. Windows PC에서 소스로 실행하기

### 처음 한 번 준비

1. [Node.js 공식 홈페이지](https://nodejs.org/)에서 **24 LTS** 버전의 Windows 설치 파일을 받습니다. 설치 화면의 기본 옵션대로 진행하세요. 최소 버전은 24.10.0입니다.
2. 제공된 프로젝트 ZIP의 압축을 풉니다. 예: `문서\asset-strategy-dashboard`. ZIP 안에서 바로 실행하지 말고 먼저 **모두 압축 풀기**를 선택하세요.
3. 압축을 푼 폴더를 엽니다. **`package.json`과 `README.md`가 함께 보이는 폴더**여야 합니다.
4. 파일 탐색기 위쪽 주소 표시줄을 클릭하고 `cmd`를 입력한 뒤 Enter를 누릅니다. 해당 폴더에서 명령 프롬프트가 열립니다.
5. 아래 명령을 한 줄씩 입력하고 각 명령이 끝날 때까지 기다립니다.

```sh
node --version
npm --version
npm ci
npm run dev -- --open
```

`npm ci`는 최초 설치 또는 의존성이 바뀌었을 때만 필요하며 인터넷이 필요합니다. `npm run dev -- --open`을 실행하면 시세 서버와 웹앱이 함께 켜지고 브라우저가 자동으로 열립니다. 자동으로 열리지 않으면 터미널에 표시된 **Local 주소**를 복사해 Chrome 또는 Edge 주소창에 붙여 넣으세요. 이것은 자신의 PC 안에서 실행되는 주소입니다.

**앱을 사용하는 동안 검은 명령창을 열어 두세요.** 종료하려면 명령창에서 `Ctrl+C`를 누릅니다.

### 다음에 다시 실행하기

`실행하기.cmd`를 더블클릭하거나, 같은 폴더에서 명령 프롬프트를 열고 다음 한 줄만 실행합니다.

```sh
npm run dev -- --open
```

같은 브라우저와 주소를 사용하면 이전 입력값을 불러옵니다. 이미 실행 중인 창이 있으면 그 창을 사용하세요. 다른 포트에서 열면 저장 공간도 달라집니다.

### 자주 생기는 문제

- **`node` 또는 `npm`을 찾을 수 없음**: Node.js 설치 후 명령창을 닫았다 다시 여세요. 그래도 안 되면 PC를 재시작하세요.
- **PowerShell에서 스크립트를 실행할 수 없다고 나옴**: 실행 정책을 바꿀 필요 없이 위 설명대로 `cmd` 명령 프롬프트를 사용하세요. PowerShell에서는 `npm.cmd ci`, `npm.cmd run dev -- --open`으로 실행해도 됩니다.
- **`package.json`을 찾을 수 없음**: 압축을 푼 안쪽 프로젝트 폴더로 이동하세요.
- **빈 화면 또는 오래된 화면**: 터미널 오류를 확인하고 새로고침하세요. 브라우저 저장 데이터를 지우기 전에 JSON 백업부터 하세요.
- **주가·환율 조회 실패**: 실행창을 열어 두었는지, 인터넷 연결과 회사 보안망의 Yahoo Finance 접근 허용 여부를 확인하세요. 제공처가 요청을 제한하면 앱은 재시도하며 이전 시세를 유지합니다. HTML 파일만 여는 방식이면 `실행하기.cmd`로 다시 실행하세요.
- **포트 사용 중 오류**: 이미 실행한 앱 창을 이용하거나 이전 실행창에서 Ctrl+C로 종료하세요. 알 수 없는 프로세스를 임의로 종료하지 마세요.
- **저장 실패 알림**: 시크릿 모드, 저장소 차단, 용량 부족을 확인하고 현재 값을 JSON으로 백업하세요.

macOS/Linux도 Node.js 설치 후 프로젝트 폴더의 터미널에서 같은 `npm ci`, `npm run dev -- --open` 명령을 사용합니다.

| 메뉴               | 기능                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| 자산 현황          | 현금·CNTN·CC·추가 주식·환율 수정, 총자산·부채·순자산·목표 잔액·달성률         |
| CNTN·CC 시뮬레이터 | 독립 시나리오 가격 입력, 6×6 조합표, 1억원 목표 가격 역산                |
| 분할매도 전략      | CNTN/CC 단계 추가·삭제, 상승률·매도 비율 수정, 확보 현금·대출 상환 결과  |
| 대출 관리          | 기존 대출 수정·삭제, 신규 대출 등록, 최대 600개월 상환표                 |
| 레버리지 분석      | 1년 만기일시 대출 투자, -50%~+50% 수익률별 이자 차감 손익                |
| 아파트 매수 비교   | 투자 유지/3억/4억/4.5억/5억/사용자 주택 비교, 자금 부족 검사, 막대그래프 |
| 5년 순자산 전망    | 연도별 추이와 표, 주식·집값 6×6 민감도, 주담대 금리 3·4·5·6% 비교        |

‘자산 현황’의 가격은 현재 평가 기준입니다. ‘CNTN·CC 시뮬레이터’의 가격은 따로 저장되므로 현재 자산을 바꾸지 않습니다. ‘현재 가격 가져오기’로 복사할 수 있습니다. 매도 및 레버리지 시뮬레이션은 실제 수량·대출을 변경하지 않습니다. 주택 조건과 비교기간은 아파트 비교/전망 화면이 공유합니다. 비교기간을 바꾸면 제목과 결과도 해당 기간으로 갱신됩니다.

금액은 원/만원/억원으로 축약합니다. 축약 금액 위에 마우스를 올리면 정확한 원 단위 금액을 확인할 수 있습니다. 대출표와 연도별 표는 원 단위로 표시합니다. 표가 넓으면 표 안에서 가로 스크롤하세요.

### 주식 추가하기 (휴대폰도 동일)

1. **자산 현황 → 내 주식 추가·관리**로 이동합니다.
2. 거래소를 고르고 종목코드를 입력합니다. 애플은 **미국 / AAPL**, 삼성전자는 **국내 코스피 / 005930**입니다. 국내 코스닥 종목은 코스닥을 선택합니다.
3. 보유 수량을 입력한 뒤 **시세 조회 후 추가**를 누릅니다. 조회에 성공한 종목만 자동 모드로 등록됩니다. ETF도 지원하며 종목명 검색 대신 종목코드를 사용합니다.
4. 종목 카드에서 수량을 수정하거나 자동/수동 방식을 변경할 수 있습니다. 미국 소수점 주식도 입력할 수 있습니다. 삭제 시 **자산에서 제외**를 누르면 평가에서 빠집니다. 실제 주문을 실행하지 않습니다.
5. 추가 주식은 총자산·순자산·목표 역산·CNTN/CC 매도 결과·주택 비교에 반영됩니다. CNTN은 이미 기본 자산에 있어 중복 등록할 수 없습니다. 최대 20종목입니다.

**연금저축·IRP 항목은 삭제했습니다.** 이전 v1 저장값이나 백업을 열면 연금 금액만 제외하며 현금·대출·기존 입력값은 유지합니다. 그 금액을 현금으로 옮기지는 않습니다.

인터넷이 없거나 제공처에 없는 종목은 **수동 입력**으로 코드·수량·가격을 등록할 수 있습니다. 지원 통화는 미국 USD와 국내 KRW입니다. 자동 가격은 별도 캐시이며, 자동 등록 시 수동 기본가격은 0입니다. 캐시가 없는 기기에서 백업을 복원하고 조회에도 실패하면 이 0원이 적용되고 미확인 상태를 표시하므로 수동 가격을 입력하세요. 자동/수동 전환은 기존 수동값을 보존합니다.

## 5. 주요 계산식과 가정

계산은 `src/strategy/finance.ts`에 모았습니다. 금리는 연 %, 통화는 원, CNTN과 미국 주식 가격은 USD입니다. 중간 계산은 소수 정밀도를 유지하고 화면 금액은 반올림합니다. 대출 원리금은 원 단위로 정산합니다.

### 자산과 목표

```text
CNTN 평가액 = 보유 주식 수 × CNTN USD 가격 × USD/KRW
CC 평가액 = 보유 개수 × CC KRW 가격
추가 주식 평가액 = Σ(보유 수량 × 가격 × 통화 환산계수)
환산계수 = 미국 USD 주식은 USD/KRW 환율, 국내 KRW 주식은 1
총자산 = 현금 + 추가 주식 평가액 + CNTN 평가액 + CC 평가액
총부채 = 등록한 대출 원금의 합계
순자산 = 총자산 − 총부채
1억원까지 남은 금액 = max(0, 1억원 − 순자산)
목표 달성률 = 순자산 ÷ 1억원 × 100
```

순자산과 달성률은 음수도 표시합니다. 진행 막대만 0~100% 범위로 표시합니다.

```text
필요 CNTN 가격 = max(0, (1억원 + 부채 − 현금 − 추가 주식 평가액 − CC 평가액) ÷ (CNTN 수량 × 환율))
필요 CC 가격 = max(0, (1억원 + 부채 − 현금 − 추가 주식 평가액 − CNTN 평가액) ÷ CC 수량)
```

보유 수량이 0이고 목표가 미달이면 ‘달성 불가’입니다. 다른 자산으로 목표에 도달했다면 필요한 가격은 0입니다. 제안 실행 가격은 CNTN 0.01달러, CC 1원 단위로 **올림**하고 원래 계산값도 표시합니다.

### 분할매도

- 모든 매도 비율은 **최초 보유 수량** 기준입니다. 10% 후 추가 15%는 최초 수량의 누적 25%를 뜻합니다.
- 단계 가격 = 현재 입력 가격 × (1 + 상승률/100).
- 매도대금 = 매도 수량 × 단계 가격 × 환율(CNTN만).
- 누적 확보 현금 = 지금까지의 매도대금 합계. 잔여 수량 = 최초 수량 − 누적 매도 수량.
- 매도 후 순자산 = 기존 현금 + 추가 주식 평가액 + 다른 자산 현재 평가액 + 누적 매도대금 + 해당 자산 잔여 수량의 단계 가격 평가액 − 부채.
- 상환 시 남은 대출 = max(0, 기존 부채 − 누적 확보 현금). 원금 상환은 현금과 부채를 동시에 줄이므로 즉시 순자산은 같습니다.
- CNTN은 정수 주 단위로 내림, CC는 소수 8자리까지 계산합니다. 총 매도 비율이 100%일 때 마지막 단계에서 전량 정산합니다.
- 비율 합계 100% 초과나 순서가 뒤집힌 상승률은 결과 계산을 중단하고 오류를 표시합니다.
- CNTN과 CC 전략은 각각 독립적으로 계산합니다. 두 결과의 확보 현금을 중복해서 합산하지 않습니다.

### 대출

현재 남은 원금과 남은 개월 수를 입력합니다. 연 금리를 `i`, 원금을 `P`, 기간을 `n`개월이라 하면 월 이율은 `r = i/100/12`입니다.

```text
원금균등: 월 원금 = floor(P/n), 월 이자 = round(직전 잔액 × r)
원리금균등: 월 납입액 = round(P × r / (1 − (1+r)^(-n)))
           월 원금 = 월 납입액 − 월 이자
만기일시: 월 이자 = round(P × r), 마지막 달에 원금 P도 상환
```

0% 원리금균등은 `round(P/n)`으로 처리합니다. 모든 방식의 마지막 달은 반올림 잔액을 정산하여 원금 합계가 정확히 `P`, 최종 잔액이 0이 됩니다. 일할 이자·거치기간·금리 변동·수수료는 제외합니다.

### 레버리지

1년 투자, 추가 대출은 만기일시상환으로 고정합니다.

```text
평가금액 = 추가 대출액 × (1 + 투자수익률/100)
투자손익 = 평가금액 − 추가 대출액
연 이자 = 추가 대출액 × 연 금리/100
이자 차감 손익 = 순자산 변화 = 투자손익 − 연 이자
```

원금은 투자금과 부채에 함께 잡히므로 이자 차감 손익에서 다시 빼지 않습니다.

### 복리·아파트 매수

단순 연 복리 함수 `compoundInvestment`는 `원금 × (1+연수익률)^년수`를 계산하며 추가저축은 **연말**에 반영합니다. 주택 비교 함수는 대출의 월 납부를 정확히 반영하기 위해 **월별** 모델을 사용합니다.

```text
처분 가능 자금 = 현금 + CNTN 평가액 + CC 평가액 + 추가 주식 평가액
실제 자기자본 = min(주택가격, ceil(max(입력 자기자본, 주택가격 × (1−LTV/100))))
초기 주담대 = 주택가격 − 실제 자기자본
초기 투자금 = 처분 가능 자금 − 실제 자기자본
월 수익률 = (1+연 주식수익률/100)^(1/12) − 1
매월 투자금 = 직전 투자금 × (1+월 수익률)
              + 연 저축액/12 − 기존 대출 납입액 − 주담대 납입액
주택 시세(t년) = 매수가격 × (1+연 집값상승률/100)^t
순자산(t년) = 주택 시세 + 투자금 − 남은 주담대 − 남은 기존 대출
```

- 최소 자기자본이 LTV 조건에 미달하면 실제 투입액을 늘립니다. **LTV는 사용자의 비교 가정**이며 규제·DSR·은행 승인 여부를 의미하지 않습니다.
- 투자 유지 시나리오는 집과 주담대 없이 같은 초기 자산·기존 대출·저축액·투자수익률을 사용합니다.
- 현금과 CNTN·CC·추가 주식을 하나의 투자자금으로 보고 남은 전액에 주식 기대수익률을 적용합니다.
- 연간 저축액은 **생활비 차감 후, 모든 대출 원리금 납부 전** 금액입니다. 이미 대출을 뺀 저축액을 입력하면 상환액을 이중 차감하게 되므로 주의하세요.
- 대출 A와 B도 매월 상환합니다. B 원금은 입력한 만기에 차감합니다. 주담대는 원리금균등입니다.
- 초기 또는 중간 월에 자금이 모자라면 ‘자금 부족’으로 표시하고 순자산 그래프에서 제외합니다. 미래 저축으로 회복해도 중간에 자금이 필요한 경우는 실행 가능으로 판정하지 않습니다.
- 취득세·보유세·중개비·수수료·투자 세금·유지비·임대차 자금·월세 차이는 제외합니다. 주거 생활비는 두 시나리오가 같다고 가정합니다. 정확한 매수 결정용 현금흐름 계산에는 이 항목들을 추가해야 합니다.

민감도 표는 선택한 주택가격과 비교기간을 기준으로 계산합니다. 주식×집값 표에서는 주담대 금리를 고정하고, 금리 그래프에서는 주식·집값 수익률을 고정합니다.

## 6. 데이터 저장과 백업

- 저장 키: `asset-strategy-dashboard-v1`. 유효한 숫자 변경 및 자동/수동 모드 변경 시 자동 저장합니다.
- 추가 주식 입력은 `holdings.stocks`에 저장되고, 종목별 마지막 시세는 `asset-strategy-stock-quotes-v1`에 별도 저장됩니다. 백업에는 수량·수동 가격·모드가 포함됩니다.
- 검증한 마지막 시세는 별도 `asset-strategy-market-quotes-v1` 캐시에 15초마다, 페이지 종료 시 저장합니다. 시세의 원래 가격 기준 시각과 조회 시각을 유지합니다. 캐시 접근이 차단되어도 입력값의 백업 기능은 사용할 수 있습니다.
- 잘못된 입력은 설명을 표시하고 마지막 유효값으로 계산합니다. 서버로 전송하지 않습니다.
- JSON 백업에는 모든 사용자 입력 자산, 대출, 매도 계획, 가격 시나리오, 주택 가정과 자동/수동 모드가 들어갑니다. 시세 캐시는 사용자 입력과 별도이며 복원 후 다시 조회합니다. **백업 복원은 현재 새 앱 데이터를 교체**합니다.
- 형식·버전·숫자 범위를 검증하며 잘못된 파일은 거부합니다. 손상된 기존 저장값은 자동으로 덮어쓰지 않습니다.
- 예전 모아 앱의 `moa-portfolio-v1` 키를 삭제하거나 변환하지 않습니다. 하단 **이전 모아 기록 백업**으로 원본 JSON을 보관할 수 있습니다. 두 앱의 데이터 모델이 달라 자동 이관하지 않습니다.
- 브라우저·기기·사이트 주소가 다르면 저장소가 다릅니다. 이동할 때 JSON 백업과 복원을 사용하세요. 시크릿 모드는 창을 닫으면 기록이 사라질 수 있습니다.

## 8. 시세 연결과 향후 확장

| 항목    | 제공처/종목                                               | 갱신 및 한계                                                                          |
| ------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| CC      | 업비트 `KRW-CC` 캔톤                                      | 공개 WebSocket ticker, 화면 최대 1초 주기 반영. 연결 장애 시 서버 REST 15초 주기 조회 |

| USD/KRW | Yahoo Finance `KRW=X`                                     | 60초 주기 조회. 제공처의 최근 외환 가격                                               |

주식·환율은 Yahoo Finance 공개 chart 조회 주소를 사용합니다. 공개 조회 주소는 공식 유료 시장데이터 계약이 아니며 변경·중단·지연될 수 있습니다. **자동 조회 주기와 거래소의 진정한 실시간 시세 보장은 다릅니다.** 가격 기준 시각, 마지막 조회 시각, 정규장 밖/지연/실패 상태를 한국시간으로 표시합니다. 장 마감이나 휴일에는 최근 정규장 가격이 유지됩니다.

- CNTN: `https://query1.finance.yahoo.com/v8/finance/chart/CNTN?interval=1m&range=1d`
- 환율: `https://query1.finance.yahoo.com/v8/finance/chart/KRW%3DX?interval=1m&range=1d`
- Yahoo 기본 호스트 실패 시 `query2.finance.yahoo.com`으로 재시도합니다.
- CC REST: `https://api.upbit.com/v1/ticker?markets=KRW-CC`
- CC 스트림: `wss://api.upbit.com/websocket/v1`. 구독은 `KRW-CC`와 연결 확인용 `KRW-BTC` 코드뿐입니다.
- 종목·통화·가격 범위·시각 검증에 실패한 응답이나 역순 시세는 적용하지 않습니다. 캐시 조회 시각을 새로운 시각으로 위조하지 않습니다.
- 자동 가격은 평가용 입력에만 겹쳐 적용합니다. 수동 가격, 보유 수량, 원금, 저장한 미래 시나리오를 덮어쓰지 않습니다.
- 서버는 기본 3개 시세와 검증된 추가 주식 종목코드만 읽으며 외부 URL을 매개변수로 받지 않습니다. 추가 주식은 종목별 60초 캐시, 최대 4개 동시 조회, 서버 캐시 128종목 제한을 적용합니다.
- 서버 기본 바인딩은 자신의 PC(`127.0.0.1`)입니다. `휴대폰연결.cmd` 또는 `node scripts/run.mjs --lan`은 같은 Wi-Fi에서 접속할 수 있도록 바인딩하고 사설 IPv4 주소를 표시합니다. 외부 인터넷 공개에는 별도 서버 운영과 HTTPS 설정이 필요합니다. GitHub Pages는 이 Node 서버를 실행하지 않습니다.
- Node 24의 공식 `--use-env-proxy`, `--use-system-ca`를 사용해 설정된 프록시와 인증서를 존중합니다. TLS 검증을 비활성화하지 않습니다. 일반 PC에는 별도 프록시 설정이 필요 없습니다.

`src/services/marketData.ts`의 `MarketDataProvider` 인터페이스로 국내주식·부동산 실거래 같은 제공처를 추가할 수 있습니다. 실제 금융계좌 자동 연결은 별도 기능입니다. 네이버페이의 공개 개발자 API에서는 개인 계좌·잔액 가져오기를 확인하지 못했으므로 계좌 잔액은 수동 입력을 유지합니다. 승인된 마이데이터/오픈뱅킹 계약·인증 서버 없이 연결된 것처럼 표시하지 않습니다.

### 빌드 후 실행 및 서버 설정

```sh
npm ci
npm run build
npm start
```

시세 서버와 빌드된 화면이 기본 포트 5173에서 함께 켜집니다. 개발 실행은 Vite 기본 포트 5173 + 내부 시세 포트 8787을 사용합니다. 두 실행 방식을 동시에 켜지 마세요. 개발 서버는 비어 있는 다음 포트를 선택할 수 있으나 주소가 달라지면 브라우저 저장소도 달라집니다.

고급 설정: `ASD_PORT`는 시세 서버 포트, `ASD_HOST`는 바인딩 주소입니다. 개발 실행의 내부 프록시 포트는 실행 도구가 자동으로 전달합니다. 설정값이나 인증서 문제를 해결하려고 비밀키를 코드에 넣거나 TLS 검증을 끄지 마세요.

최종 ZIP의 `dist/`가 있으면 패키지를 설치하지 않고 `node scripts/run.mjs --open`으로 바로 실행할 수도 있습니다. Windows 실행 도우미는 이 방식을 사용합니다. 화면이나 금융 코드를 수정한 경우에는 `npm ci` 후 `npm run build`로 dist를 다시 만들어야 변경이 반영됩니다.
